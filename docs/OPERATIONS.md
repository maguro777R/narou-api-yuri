# 運用ガイド

## ふだんすること

[公開サイト](https://maguro777r.github.io/narou-api-test/) を開くだけで使えます。更新は GitHub が行います。

| タイミング | 自動で行うこと |
| --- | --- |
| 毎週火曜 6:23 ごろ（日本時間） | API 取得 → 集計 → テスト済みのページを公開 |
| 毎日 6:53 ごろ（日本時間） | 自分の公開ページの取得日時を確認。API は取得しない |
| 画面・取得処理を `main` に反映したとき | 新しい実装で取得・公開 |
| 手動更新を押したとき | 同じ取得・公開を実行 |

GitHub 側の混雑によって開始が遅れたり、実行されなかったりすることがあります。時刻ぴったりの更新は保証されません。

## 今すぐ更新する

1. リポジトリの [Actions](https://github.com/maguro777R/narou-api-test/actions) を開きます。
2. 左側で **週間の観測と公開** を選びます。
3. **Run workflow** を押します。ブランチは `main`、モードは `refresh` を選びます。
4. 数分待ち、実行結果が緑色になったら公開サイトを再読み込みします。

API の負荷を抑えるため、短時間に繰り返し押さないでください。

## 更新に失敗したら

Actions で赤くなった実行を開くと、どの手順で止まったか分かります。

- **取得で失敗:** API の一時的な停止や応答の変化が考えられます。時間を置いて 1 回再実行してください。
- **テストで失敗:** ソースコードの変更を確認します。失敗した実行では新しいページを公開しません。
- **公開で失敗:** リポジトリの **Settings → Pages → Source** が **GitHub Actions** になっているか確認します。
- **ローカルで「出力先に想定外のファイル」:** 出力フォルダに古いデータなどが混ざっています。`--output /tmp/narou-preview` のように空の専用フォルダを指定します。無関係なファイルは自動削除しません。

途中まで取得できた場合も、不完全な集計で公開ページを上書きしません。以前の正常なページが残ります。GitHub の通知設定で Actions の失敗通知を受け取れるようにしておくと気づきやすくなります。

取得から 8 日以上経つと、画面に更新待ちの表示が出ます。日次の確認で取得から 13 日以上経っていた場合、作品情報を含まない休止案内に置き換えます。日次処理が止まっていても、JavaScript が動くブラウザでは 14 日以上経つと結果を非表示にします。

ただしブラウザでの非表示だけでは、サーバーにある HTML の削除にはなりません。Actions 全体が停止した場合、下の手順で公開を止めてください。

## 長く使わないとき・公開を止めたいとき

1. Actions の **週間の観測と公開** を開き、右上のメニューから **Disable workflow** を選びます。
2. **Settings → Pages** の **Unpublish site** でサイトを非公開にします。

これで自動更新も公開も止まります。コードのコミットは残るので、再開時に作り直す必要はありません。

サイト自体を残して「更新待ち」の案内に変えたい場合は、先に **Run workflow → maintenance** を実行し、緑色になった後でワークフローを無効にします。`maintenance` を実行しただけでは次の定期更新は止まりません。

## GitHub の自動停止に注意

公開リポジトリに 60 日間活動がないと、定期実行が自動的に無効になることがあります。実行が続いているだけでは、停止を避けられるとは限りません。月に 1 回程度 Actions の履歴を確認し、停止していたら **Enable workflow** で有効にして、`refresh` を手動実行します。

この初版では、停止回避のためだけの空コミットは作りません。サイトを使わなくなった場合は、忘れずに公開も止めてください。

出典: [GitHub Actions の定期実行の仕様](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)

## 初めて公開するときの設定

1. **Settings → Pages → Build and deployment → Source** で **GitHub Actions** を選びます。
2. `.github/workflows/` を含むコードを `main` に反映します。
3. **週間の観測と公開** が成功したら、Pages の画面に表示される URL を開きます。

API キーや個人のアクセストークンを Secrets に追加する必要はありません。公開には GitHub が実行ごとに用意する権限を使います。リポジトリへの書き込み権限や自動コミットも不要です。

別リポジトリで使うときは、`scripts/narou.py` の `REPOSITORY_URL` と README のリンクを自分のリポジトリに直します。利用条件と問い合わせ先も確認してください。
